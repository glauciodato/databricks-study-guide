Aula - Visão Geral sobre Ingestão de Dados Empresariais

Visão Geral

Nesta aula, você aprenderá como os Conectores Gerenciados do LakeFlow Connect e o Partner Connect simplificam a ingestão de dados empresariais, permitindo uma integração rápida e confiável de bancos de dados e aplicações para o Databricks Lakehouse por meio de opções flexíveis, totalmente gerenciadas e com suporte de parceiros.

Objetivos de Aprendizagem

Ao final desta aula, você será capaz de:

  1. Explicar a necessidade de conectores gerenciados ao ingerir dados de bancos de dados empresariais e aplicações SaaS além do armazenamento de objetos em cloud
  2. Descrever os benefícios dos Conectores Gerenciados do LakeFlow Connect, incluindo configuração simplificada, configuração orientada por interface gráfica e infraestrutura totalmente gerenciada
  3. Comparar as arquiteturas de ingestão de dados SaaS e de banco de dados utilizadas pelos Conectores Gerenciados do LakeFlow Connect
  4. Descrever o Partner Connect como uma alternativa para fontes de dados sem um conector gerenciado nativo

A. Visão Geral da Ingestão de Dados no Databricks

Até agora, discutimos a ingestão de dados do cloud object storage no Databricks usando técnicas como CREATE TABLE, COPY INTO e Auto Loader.

Mas e quanto à ingestão de dados de bancos de dados ou aplicações empresariais?

Quais técnicas podemos usar para lidar com essas fontes?

B. LakeFlow Connect Managed Connectors

O primeiro método para ingestão de dados corporativos é por meio dos LakeFlow Connect Managed Connectors.

Os LakeFlow Connect Managed Connectors são integrados ao Databricks e foram projetados para simplificar o processo de ingestão de dados de uma ampla variedade de bancos de dados e aplicações corporativas.

Eles oferecem uma experiência de baixo código e totalmente gerenciada, reduzindo a necessidade de configuração manual ou código de integração personalizado.

D. LakeFlow Connect Managed Connectors: Ingestão SaaS

Vamos começar com uma visão geral da arquitetura de conectores gerenciados do LakeFlow Connect para aplicações SaaS.

O LakeFlow Connect permite a ingestão de dados de fontes externas e publicamente acessíveis, como APIs ou endpoints OLAP, em tabelas UC de transmissão, utilizando Declarative Pipelines serverless. É possível configurar esses pipelines por meio da interface do usuário (UI) ou da API. Os conectores gerenciados utilizam leituras e gravações incrementais eficientes para tornar a ingestão de dados mais rápida, escalável e econômica, mantendo os dados atualizados para consumo downstream.

O LakeFlow Connect coleta dados de fontes externas para Tabelas UC de transmissão usando um pipeline Declarative Pipelines com compute serverless: - Um job Declarative Pipelines Serverless do LakeFlow **coleta as credenciais** do Unity Catalog. - O job **acessa** a fonte de dados publicamente acessível (por exemplo, API, porta OLAP aberta, etc.). - O serviço transforma os dados e os armazena em uma **Tabela UC de transmissão**.
Documentação

Consulte a documentação dos componentes do conector SaaS gerenciado.

EXPANDIR PARA NOTAS ADICIONAIS
Para suportar esse fluxo, introduzimos um novo tipo de pipeline: o pipeline de ingestão gerenciada. Seu papel principal é conectar-se a fontes SaaS públicas (como Salesforce ou Workday), extrair os dados e ingeri-los diretamente em uma tabela de transmissão. Esses pipelines são amplamente predefinidos e gerenciados pelo Databricks, permitindo o tratamento transparente das complexidades específicas de cada fonte. Por fim, para conectores SaaS, toda a movimentação de dados ocorre no Data Plane. O Control Plane é utilizado apenas para configuração do pipeline, monitoramento (por exemplo, leitura de logs de eventos) e gerenciamento.

E. Arquitetura de Ingestão de Banco de Dados

Agora vamos ver como a arquitetura muda ao utilizar um conector de banco de dados gerenciado pelo LakeFlow Connect.

Assim como nos conectores SaaS, essa arquitetura foi projetada para mover dados para tabelas UC de transmissão — mas desta vez a partir de bancos de dados externos, em vez de APIs públicas.

LakeFlow Connect coleta dados de bancos de dados externos para tabelas de transmissão do Unity Catalog:
  1. O job Declarative Pipelines de compute clássico coleta as credenciais do Unity Catalog
  2. Ele usa as credenciais para conectar e coletar dados das suas fontes de banco de dados
  3. O estado mais recente e os dados de staging são salvos no seu volume do Unity Catalog
  4. Um job serverless Declarative Pipelines processa os dados coletados para suas tabelas de transmissão do Unity Catalog
Documentação

Consulte a documentação dos componentes do conector de banco de dados gerenciado.

EXPANDIR PARA NOTAS ADICIONAIS
A arquitetura de ingestão de banco de dados é mais complexa do que a de SaaS porque precisa se conectar a bancos de dados que podem estar on-premises ou em uma cloud privada. Componentes-Chave Introduzidos Estamos introduzindo dois novos elementos arquiteturais aqui:
  1. Gateway de Ingestão:
    • Um Pipeline dedicado que se conecta ao banco de dados para extrair:
      • Metadados
      • Snapshots
      • Logs de alterações — Tudo isso é armazenado temporariamente no volume do Unity Catalog (UC).
  2. Volume do Unity Catalog:
    • Atua como a camada intermediária de staging, permitindo que o próximo Pipeline colete e transmita os dados.
    • É protegido usando os mecanismos padrão do UC e, por default, o acesso é limitado ao usuário que executa o Pipeline.
Então, por que adicionamos esse passo de gateway? Em primeiro lugar, ele auxilia com a rede. Muitos Clientes possuem bancos de dados que (1) estão atrás de um firewall, (2) não são acessíveis publicamente pela internet, entre outros casos. Se você não tem uma opção como Private Link, podemos implantar o gateway dentro da sua rede. O gateway também nos ajuda a limitar a carga que estamos impondo ao banco de dados. Afinal, você provavelmente deseja limitar o número de conexões diretas à sua fonte de dados. Ao separar o gateway do Pipeline, conseguimos ter um único gateway se comunicando com o banco de dados — e depois distribuir para N pipelines para garantir essa escalabilidade. (Para contextualizar, isso não é um problema em um conector SaaS porque a carga é tipicamente controlada com Limites de API. Mas mesmo assim, estamos usando esses limites da forma mais eficiente possível.)

F. Ingestão de Dados com Partner Connect

Se não houver um conector gerenciado disponível para sua fonte de dados específica, você também pode usar o Partner Connect.

F1. Visão Geral do Partner Connect

O Partner Connect permite criar contas de avaliação com parceiros de tecnología selecionados do Databricks e conectar seu Databricks workspace às soluções de parceiros pela interface do Databricks. Isso permite testar soluções de parceiros usando seus dados no Databricks lakehouse e, em seguida, adotar as soluções que melhor atendam às suas necessidades de negócio.

  • O Partner Connect permite que você crie contas de avaliação com parceiros de tecnología selecionados do Databricks.
  • Ele permite que você conecte seu Databricks workspace às soluções dos parceiros diretamente pela interface do Databricks.
  • Isso permite que você teste as soluções dos parceiros usando seus dados no Databricks Lakehouse.
  • Você pode então avaliar e adotar as soluções que melhor atendam às suas necessidades de negócio.

F2. Partner Connect Ecosystem

Nossos parceiros de ingestão continuam sendo fundamentais. Eles oferecem uma gama muito ampla de conectores, e esses conectores tendem a ter funcionalidades avançadas mantidas por equipes dedicadas de engenheiros experientes.

G. Conclusão

Nesta aula, você aprendeu como ingerir dados corporativos no Databricks além do armazenamento de objetos cloud:

  • Conectores Gerenciados do LakeFlow Connect simplificam a ingestão de dados a partir de bancos de dados corporativos e aplicações SaaS com uma experiência totalmente gerenciada, orientada por interface ou por API.
  • Arquitetura de ingestão de dados SaaS: Um job serverless de Declarative Pipelines coleta credenciais do Unity Catalog, acessa a fonte de dados pública e grava em tabelas de transmissão do Unity Catalog.
  • Arquitetura de ingestão de dados de banco de dados: Utiliza um Gateway de Ingestão adicional (compute clássico) para conectar-se a bancos de dados privados, com gerenciamento de staging e estado em volumes do Unity Catalog, antes que um pipeline serverless grave nas tabelas de transmissão do Unity Catalog.
  • Partner Connect oferece uma alternativa quando nenhum conector gerenciado nativo está disponível, proporcionando um rico ecossistema de soluções de parceiros (Informatica, Qlik, Rivery, Alteryx, Prophecy, Fivetran, entre outros).
