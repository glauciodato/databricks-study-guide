Lab - Construindo um Pipeline de E-commerce Multi-Source com Spark Declarative Pipelines

Cenário do Laboratório

Você é um engenheiro de dados trabalhando para uma empresa de e-commerce que recebe pedidos de dois canais: seu site e o aplicativo mobile. Esses canais armazenam dados em formatos diferentes e podem ter algumas semelhanças e diferenças na forma como capturam informações de pedidos. Seu papel é construir um pipeline de dados de streaming usando Spark Declarative Pipelines que possa processar dados desses diferentes canais e gerar relatórios semanais de receita para os stakeholders de negócio.

Este lab demonstrará técnicas avançadas, incluindo ingestão multi-flow, joins entre stream e static, data quality expectations e materialized views para analytics.

E. Camada Silver — Expectations e Stream-Static Join

A camada Silver limpará e validará nossos dados usando expectations, e depois os enriquecerá com informações do catálogo de produtos através de um stream-static join.

E1. Entenda as Data Quality Expectations

Data quality expectations garantem que apenas dados válidos fluam pelo nosso pipeline. Aqui estão as constraints que vamos implementar:

Nome da Constraint Expectation Ação Motivo
valid_order_id order_id IS NOT NULL FAIL UPDATE Chave primária — NULL quebra todos os joins posteriores
valid_sku sku IS NOT NULL DROP ROW Sem referência de produto = inutilizável para analytics
positive_quantity quantity >= 1 DROP ROW Quantidade zero ou negativa não é uma venda válida
positive_unit_price unit_price > 0 WARN (padrão) Sinaliza anomalias de preço sem bloquear o pipeline
valid_total_amount total_amount >= 0 WARN (padrão) Sinaliza totais negativos para revisão

E3. Crie a Tabela Silver

Instruções: - Crie uma streaming table Silver chamada orders_clean no schema lab_2_silver. - Use CREATE OR REFRESH STREAMING TABLE e selecione a partir de STREAM lab_1_bronze.combined_orders_raw. - Adicione constraints de qualidade de dados usando CONSTRAINT e EXPECT para as colunas-chave. - Use CLUSTER BY AUTO para clustering automático. - Converta os campos brutos para os tipos corretos com TRY_CAST. - Adicione um comentário na tabela descrevendo-a.

Requisitos: - Tabela: orders_clean - Colunas: converta campos como order_date (TIMESTAMP), quantity (INT), unit_price, discount_amount, total_amount (DOUBLE), ship_date (DATE). - Constraints: - valid_order_id: order_id IS NOT NULL, ON VIOLATION FAIL UPDATE - valid_sku: sku IS NOT NULL, ON VIOLATION DROP ROW - positive_quantity: quantity >= 1, ON VIOLATION DROP ROW - positive_unit_price: unit_price > 0 (WARN) - valid_total_amount: total_amount >= 0 (WARN)

CÓDIGO RESPOSTA - Tabela Silver com Expectations e Liquid Clustering Habilitados
EXPANDIR PARA CÓDIGO DA SOLUÇÃO 

-- ----------------------------------------------------------------
-- PASSO 1: Pedidos limpos Silver
-- ----------------------------------------------------------------
CREATE OR REFRESH STREAMING TABLE lab_2_silver.orders_clean
(
  -- FAIL: order_id é a chave primária
  CONSTRAINT valid_order_id
    EXPECT (order_id IS NOT NULL)
    ON VIOLATION FAIL UPDATE,

  -- DROP: linhas sem SKU são inutilizáveis para analytics
  CONSTRAINT valid_sku
    EXPECT (sku IS NOT NULL)
    ON VIOLATION DROP ROW,

  -- DROP: quantidade menor que 1 não é uma venda válida
  CONSTRAINT positive_quantity
    EXPECT (quantity >= 1)
    ON VIOLATION DROP ROW,

  -- WARN: sinaliza anomalias de preço; a linha passa
  CONSTRAINT positive_unit_price
    EXPECT (unit_price > 0),

  -- WARN: sinaliza totais negativos; a linha passa
  CONSTRAINT valid_total_amount
    EXPECT (total_amount >= 0)
)
COMMENT "Pedidos limpos Silver - convertidos de tipo, validados por qualidade, com liquid clustering."
CLUSTER BY AUTO
AS
SELECT
  order_id,
  TRY_CAST(order_date      AS TIMESTAMP) AS order_date,
  customer_id,
  sku,
  model,
  category,
  order_type,
  channel,
  TRY_CAST(quantity        AS INT)       AS quantity,
  TRY_CAST(unit_price      AS DOUBLE)    AS unit_price,
  discount_code,
  TRY_CAST(discount_amount AS DOUBLE)    AS discount_amount,
  TRY_CAST(total_amount    AS DOUBLE)    AS total_amount,
  payment_method,
  order_status,
  city,
  region,
  TRY_CAST(ship_date       AS DATE)      AS ship_date,
  browser,
  os,
  session_id,
  app_version,
  device_model,
  source_file,
  ingestion_time
FROM STREAM lab_1_bronze.combined_orders_raw;

E5. Faça o Join da Tabela Orders Clean com o Catálogo de Produtos

Vamos enriquecer a tabela orders_clean com atributos do catálogo de produtos usando um stream-static join.

Principais Características: - Use um LEFT JOIN stream-static para manter todos os pedidos, mesmo que o SKU esteja ausente no catálogo. - Adicione atributos de produto do catálogo: - brand - catalog_category - list_price - is_active (como sku_is_active) - Calcule price_vs_catalog como a diferença entre o unit_price do pedido e o list_price do catálogo.


-- ----------------------------------------------------------------
-- STEP 3: Enriched orders — stream-static join
-- Streaming side : orders_clean
-- Static side    : product_catalog_ref (re-read on every trigger)
-- LEFT JOIN retains all orders even if the SKU is not in catalog.
-- ----------------------------------------------------------------
CREATE OR REFRESH STREAMING TABLE lab_2_silver.orders_enriched

-- ----------------------------------------------------------------
-- VIEW GOLD: Receita Diária por Categoria
-- Público: dashboards executivos, gerentes de categoria
-- ----------------------------------------------------------------
CREATE OR REPLACE MATERIALIZED VIEW lab_3_gold.weekly_revenue_by_category
COMMENT "Gold MV: receita bruta diária, unidades e contagem de pedidos por categoria e canal."
AS
SELECT
    order_date,
    catalog_category                                        AS category,
    brand,
    order_type                                              AS channel,
    region,
    COUNT(DISTINCT order_id)                                AS total_orders,
    SUM(quantity)                                           AS units_sold,
    ROUND(SUM(total_amount), 2)                             AS gross_revenue,
    ROUND(SUM(discount_amount), 2)                         AS total_discounts,
    ROUND(SUM(total_amount) - SUM(discount_amount), 2)     AS net_revenue,
    ROUND(AVG(total_amount), 2)                             AS avg_order_value,
    COUNT(CASE WHEN discount_code IS NOT NULL THEN 1 END)  AS discounted_orders,
    current_timestamp()                                     AS last_refreshed

FROM lab_2_silver.orders_enriched
WHERE order_date IS NOT NULL AND catalog_category  IS NOT NULL
GROUP BY
order_date,catalog_category,brand,order_type,region;
