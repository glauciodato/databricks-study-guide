Demo - Multiplex Streaming SDP com Delta Sinks e Iceberg Reads

Visão Geral

Esta demonstração mostra como construir um pipeline de dados multiplex usando Spark Declarative Pipelines (Lakeflow). Você aprenderá a ingerir dados multiplexados de uma única fonte em uma bronze streaming table, depois demultiplexar esses dados em múltiplas silver streaming tables com base em tipos de evento, e finalmente criar views agregadas na camada gold para analytics.

A demo simula um cenário do mundo real onde múltiplos domínios de negócio (operações de loja, marketing e logística) geram eventos que são ingeridos em um único data stream. Usando o padrão de arquitetura medallion, você processará esses dados multiplexados através das camadas bronze, silver e gold, ao mesmo tempo em que habilita compatibilidade com Iceberg para analytics entre plataformas.

Objetivos de Aprendizado

Ao final desta demonstração, você será capaz de:

  • Construir pipelines de dados multiplex usando Spark Declarative Pipelines para lidar com múltiplos tipos de evento a partir de uma única fonte
  • Demultiplexar dados de streaming filtrando e transformando eventos em tabelas separadas por domínio
  • Construir Delta sinks usando a Python API para criar tabelas prontas para analytics a partir de fontes de streaming
  • Habilitar compatibilidade com Iceberg em tabelas Delta para suportar acesso a dados e analytics entre plataformas

Multiplex Pipeline Demonstration Visão Geral

Nesta demonstração, você construirá um Apache Spark™ Declarative Pipeline que implementa a arquitetura medallion completa, desde a ingestão de dados brutos até analytics curados.

  1. Ingerir arquivos multiplexados do cloud storage e escrevê-los em uma única tabela bronze.
    • Esses arquivos contêm dados multiplexados, ou seja, incluem eventos de marketing, logística e operações de loja, todos despejados em um único local na cloud.
  2. Demultiplexar a tabela bronze em tabelas intermediárias com base no grupo de eventos. Três tabelas intermediárias serão criadas na camada bronze.
  3. Transformar as tabelas intermediárias para criar tabelas silver para cada grupo de eventos, adicionando novas colunas conforme exigido pela lógica de negócio e convertendo colunas para os tipos de dados apropriados.
  4. Criar materialized views gold a partir dos dados de marketing que atualizam automaticamente e fornecem resultados prontos para analytics.
  5. Escrever a tabela de logística em um Delta sink para habilitar acesso externo via Iceberg reads.

D. Crie a Primeira Tabela Bronze para Todos os Dados de Business Events

Comece criando a bronze streaming table para ingerir dados da origem. - Esta tabela capturará dados brutos de eventos de negócio em streaming vindos de múltiplas fontes. - Vamos usar o tipo de dado VARIANT para fazer o parse de strings formatadas em JSON. - Duas colunas de metadata são adicionadas para rastrear quando novos dados são ingeridos.

  1. Copie o código SQL abaixo e cole no seu arquivo ingestion.sql.


------------------------------------------------------
-- CRIAR A TABELA BRONZE PARA OS DADOS DE BUSINESS EVENTS
------------------------------------------------------
CREATE OR REFRESH STREAMING TABLE multiplex_1_bronze.bronze_demo
TBLPROPERTIES (
  'pipelines.reset.allowed' = false,
  'delta.feature.variantType-preview' = 'supported'
) 
AS
SELECT
  CAST(key AS STRING) AS event_id,
  PARSE_JSON(CAST(value AS STRING)) AS event_data_variant,
  CAST(topic AS STRING) AS event_group,
  CAST(partition AS STRING) AS partition,
  CAST(offset AS STRING) AS offset,
  -- Adiciona colunas de metadata
  _metadata.file_name AS source_file,
  _metadata.file_modification_time AS file_mod_time
FROM STREAM read_files(
  '${business_events_source}'
);

Revise o Código

A instrução TBLPROPERTIES configura as seguintes definições: - Proteção contra Reset: A propriedade 'pipelines.reset.allowed' = false impede refreshes completos na streaming table, o que ajuda a evitar a remoção acidental de checkpoints e a truncagem dos dados da streaming table - Suporte ao Tipo Variant: 'delta.feature.variantType-preview' = 'supported' habilita o tipo de dado variant, que permite armazenar e consultar de forma eficiente dados semiestruturados como JSON. Essa propriedade precisa ser definida para desbloquear o suporte nativo a colunas variant

IMPORTANTE: Entendendo a Proteção contra Full Table Refresh

Essa proteção é particularmente importante quando sua fonte de dados bruta remove arquivos automaticamente após um determinado período. Sem essa configuração, dados que não estão mais presentes no diretório de origem não seriam reingeridos na target table durante uma operação de Run pipeline with full table refresh.

NOTA: Para orientações sobre quando usar full refreshes, consulte a documentação Should I use a full refresh?.

F1. Crie a Tabela Silver para Dados de Marketing

Nesta etapa, transformamos os eventos brutos de marketing em uma tabela silver curada, multiplex_2_silver.marketing_silver_demo, otimizada para analytics.

Veja o que a transformação silver faz:

  • Lê os dados da streaming table marketing_intermediate.
  • Usa COALESCE para criar um event_id confiável, garantindo que cada linha tenha um identificador único.
  • Seleciona os campos de negócio essenciais necessários para análise, como campanha, canal, impressões, cliques e gasto.
  • Mantém os dados no mesmo nível de detalhe (sem agregação ou filtros que alterem o número de linhas).
  • Calcula métricas importantes de marketing:
  • click_through_rate: Mede com que frequência as pessoas clicam após ver um anúncio (cliques divididos por impressões).
  • cost_per_click: Mostra quanto custa cada clique (gasto dividido por cliques).
  • Trata com segurança os casos em que impressões ou cliques são zero, para evitar erros nos cálculos de métricas.
  • Produz uma streaming table limpa e estruturada, pronta para dashboards e relatórios.

Esta tabela silver garante dados consistentes e métricas confiáveis para todos os analytics posteriores.

  1. Copie o código no seu arquivo silver_transformation.sql.


------------------------------------------------------
-- CRIAR A TABELA SILVER PARA DADOS DE MARKETING
------------------------------------------------------

CREATE OR REFRESH STREAMING TABLE multiplex_2_silver.marketing_silver_demo
AS SELECT 
  COALESCE(extracted_event_id, event_id) AS event_id,
  timestamp,
  event_group,
  event_type,
  subsidiary_id,
  campaign_id,
  channel,
  impressions,
  clicks,
  conversions,
  spend_usd,
  CASE WHEN impressions > 0 
    THEN clicks / impressions 
    ELSE 0 
  END AS click_through_rate,
  CASE WHEN clicks > 0 
    THEN spend_usd / clicks 
    ELSE 0 
  END AS cost_per_click
FROM STREAM multiplex_1_bronze.marketing_intermediate;

F2. Crie a Tabela Silver para Dados de Logística

Nesta etapa, transformamos os eventos brutos de logística em uma tabela silver limpa, multiplex_2_silver.logistics_silver_demo, otimizada para rastreamento e relatórios de supply chain.

Veja o que a transformação silver faz:

  • Lê os dados da streaming table logistics_intermediate.
  • Usa COALESCE para criar um event_id confiável, garantindo que cada registro de remessa seja unicamente identificável.
  • Aplica filtros de qualidade de dados para remover registros incompletos (filtra linhas onde warehouse_id ou batch_id estão ausentes).
  • Seleciona atributos essenciais de logística, como armazém, transportadora, ID do lote e região de destino.
  • Adiciona campos calculados:
  • is_valid_shipment: Um flag booleano que verifica se a remessa contém pacotes de fato (verdadeiro se num_packages > 0), ajudando a identificar remessas fantasmas ou erros de sistema.
  • event_date: Extrai a data do timestamp para suportar relatórios diários e particionamento.
  • Produz uma streaming table confiável e de alta qualidade, pronta para dashboards operacionais.

Esta tabela silver garante que a análise posterior seja realizada apenas sobre registros de logística válidos e completos.

  1. Copie o código no seu arquivo silver_transformation.sql.


------------------------------------------------------
-- CRIAR A TABELA SILVER PARA DADOS DE LOGÍSTICA
------------------------------------------------------

CREATE OR REFRESH STREAMING TABLE multiplex_2_silver.logistics_silver_demo
AS SELECT 
  COALESCE(extracted_event_id, event_id) AS event_id,
  timestamp,
  event_group,
  event_type,
  subsidiary_id,
  warehouse_id,
  carrier,
  batch_id,
  num_packages,
  destination_region,
  CASE WHEN num_packages > 0 THEN TRUE ELSE FALSE END AS is_valid_shipment,
  DATE(timestamp) AS event_date
FROM STREAM multiplex_1_bronze.logistics_intermediate
WHERE warehouse_id IS NOT NULL
  AND batch_id IS NOT NULL;

F3. Crie a Tabela Silver para Dados de Store Operations

Nesta etapa, transformamos os eventos brutos de store operations em uma tabela silver estruturada, multiplex_2_silver.store_ops_silver_demo, projetada para supervisão operacional e análise de força de trabalho.

Aspectos principais da transformação silver:

  • Lê os dados da streaming table store_ops_intermediate.
  • Usa COALESCE para garantir que cada operação tenha um event_id consistente e único.
  • Aplica qualidade de dados rigorosa filtrando registros com campos críticos ausentes (timestamp, ID da loja ou tipo de evento).
  • Padroniza a coluna de tempo renomeando extracted_timestamp para um campo comum timestamp.
  • Enriquece os dados com colunas derivadas para análise temporal e identificação de loja:
  • event_date e event_hour: Extraídos para suportar relatórios diários e análise de horários de pico operacional.
  • store_number: Faz o parse do store_id (usando uma função de split) para isolar o identificador numérico, facilitando relatórios.
  • Produz uma streaming table de alta qualidade, pronta para dashboards regionais e por loja.

Esta tabela silver garante que os analytics operacionais sejam baseados em registros válidos e completos, com dimensões de tempo detalhadas.

------------------------------------------------------
-- CRIAR A TABELA SILVER PARA DADOS DE STORE OPERATIONS
------------------------------------------------------

G2. Crie a View Gold para Resumo de Campanhas de Marketing

Nesta etapa, elevamos os dados à camada Gold criando uma materialized view, multiplex_3_gold.marketing_campaign_summary. Esta view agrega os dados granulares de eventos em métricas de performance de alto nível, otimizadas para relatórios executivos e dashboards.

Veja o que essa transformação faz:

  • Agrega dados da tabela marketing_silver_demo, agrupando-os por Campaign, Subsidiary e Channel para fornecer um resumo de performance claro.
  • Calcula Totais: Soma métricas de volume chave (eventos, impressões, cliques, conversões) e métricas financeiras (gasto total) para cada grupo.
  • Deriva KPIs Estratégicos:
  • ctr_percentage: A taxa de cliques (Click-Through Rate) formatada como porcentagem.
  • conversion_rate_percentage: A porcentagem de cliques que resultaram em uma conversão bem-sucedida.
  • cost_per_conversion: O valor médio gasto para adquirir uma única conversão (CPA).
  • Garante Qualidade de Dados:
  • Usa NULLIF para evitar erros de "divisão por zero" ao calcular razões.
  • Usa ROUND para formatar valores monetários e porcentagens com duas casas decimais, para uma apresentação mais limpa.

Esta materialized view serve como a "fonte da verdade" para dashboards de performance de campanhas, permitindo que stakeholders comparem a eficácia dos canais e o ROI instantaneamente.

  1. Copy the code below in your gold_view.sql file.


------------------------------------------------------
-- CRIAR MATERIALIZED VIEW PARA DADOS DE MARKETING
------------------------------------------------------

CREATE OR REFRESH MATERIALIZED VIEW multiplex_3_gold.marketing_campaign_summary
AS SELECT
  campaign_id,
  subsidiary_id,
  channel,
  COUNT(*) AS total_events,
  SUM(impressions) AS total_impressions,
  SUM(clicks) AS total_clicks,
  SUM(conversions) AS total_conversions,
  ROUND(SUM(spend_usd), 2) AS total_spend_usd,
  ROUND((SUM(clicks) * 1.0 / NULLIF(SUM(impressions), 0)) * 100, 2) AS ctr_percentage,
  ROUND((SUM(conversions) * 1.0 / NULLIF(SUM(clicks), 0)) * 100, 2) AS conversion_rate_percentage,
  ROUND(SUM(spend_usd) / NULLIF(SUM(conversions), 0), 2) AS cost_per_conversion
FROM multiplex_2_silver.marketing_silver_demo
GROUP BY campaign_id, subsidiary_id, channel;

  2. Define um Destino (Sink): A função create_sink registra um endpoint específico para seus dados — uma tabela Delta chamada logistics_delta_sink no schema Gold — separadamente da lógica que a popula.
  3. Estabelece um Flow de Streaming: O decorator @dp.append_flow cria um pipeline de dados contínuo que conecta sua lógica de processamento diretamente ao sink definido, automatizando a movimentação de dados.
  4. Habilita Lógica Append-Only: O append flow otimiza a performance adicionando novos registros conforme chegam, em vez de reprocessar ou sobrescrever dados existentes.

  5. Automatiza o Processamento Incremental: Usando readStream, o pipeline rastreia automaticamente quais dados já foram processados (usando checkpointing), garantindo que apenas novos registros da tabela Silver sejam movidos para Gold.

from pyspark import pipelines as dp

my_catalog = spark.conf.get("my_catalog")

dp.create_sink(
  name = "delta_sink_logistics",
  format = "delta",
  options = { "tableName": f"{my_catalog}.multiplex_3_gold.logistics_delta_sink" }
)

@dp.append_flow(name = "delta_sink_logistics_flow", target="delta_sink_logistics")

  spark.readStream.table("multiplex_2_silver.logistics_silver_demo")
