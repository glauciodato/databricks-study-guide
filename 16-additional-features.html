Aula - Recursos Adicionais e Ingestão em Tabelas UC Existentes

Visão Geral

O Databricks oferece recursos adicionais como Lakehouse Federation, Zerobus, Open Sharing e Databricks Marketplace para expandir as capacidades de integração de dados, compartilhamento e colaboração no Lakehouse.

Esta aula também apresenta como MERGE INTO simplifica a ingestão em tabelas UC existentes, aplicando atualizações, inserções e exclusões a partir de uma fonte em uma única operação atômica.

Objetivos de Aprendizado

Ao final desta aula, você será capaz de:

  1. Descrever os recursos adicionais do Databricks que ampliam as capacidades de integração de dados, compartilhamento e colaboração
  2. Identificar os principais componentes do Databricks Marketplace e explorar ativos de dados compartilhados
  3. Explicar a finalidade do MERGE INTO para aplicar atualizações, inserções e exclusões em tabelas UC existentes
  4. Descrever as cláusulas do MERGE INTO, incluindo atualizações em registros correspondentes, exclusões em registros correspondentes e inserções em registros não correspondentes
  5. Escrever uma instrução MERGE INTO para fazer merge de dados de uma fonte em uma tabela UC de destino

D. Atualizações, Inserções e Exclusões em tabelas UC com MERGE INTO

O comando MERGE INTO permite aplicar atualizações, inserções e exclusões de uma tabela fonte em uma tabela UC existente, tudo em uma única operação atômica.

D1. Visão Geral do MERGE INTO

MERGE INTO
Combina um conjunto de atualizações, inserções e exclusões de uma tabela fonte em uma tabela UC de destino. O MERGE INTO suporta imposição de esquema ou evolução do esquema e permite diferentes ações dependendo se uma linha é correspondida entre uma tabela fonte e uma tabela de destino:
Linhas correspondidas
UPDATE ou DELETE
Linhas não correspondidas pelo destino
INSERT
Linhas não correspondidas pela fonte
UPDATE ou DELETE
Essa funcionalidade torna o MERGE INTO ideal para lidar com slowly changing dimensions (SCDs), cargas incrementais e cenários complexos de change data capture (CDC).

D2. Exemplo Passo a Passo de MERGE INTO

Há situações em que você precisa atualizar, inserir ou excluir registros em uma tabela de destino com base em informações de outra tabela.


Neste cenário, temos:
  • Uma target_table com os usuários peter e zebi, ambos com estado "current"

  • Uma source_table com três linhas indicando alterações:
    • peter: status = "delete" (remover da tabela destino)
    • zebi: status = "update" (atualizar email para zebi@other.com)
    • samarth: status = "new" (inserir como nova linha)
O objetivo é atualizar a target_table aplicando os três tipos de alterações em uma única operação MERGE INTO.

  1. Passo 1: Declarar a Tabela de Destino e a Tabela Fonte
    
  
      
  
    • MERGE INTO target_table target - Isso declara a tabela de destino, a tabela que você deseja atualizar, inserir ou excluir registros. O alias target é atribuído para referenciá-la posteriormente na query.
      • 
  
    • USING source_table source - Isso define a tabela fonte, a tabela que contém os novos dados ou alterações que você deseja aplicar ao destino. O alias source é atribuído a ela.

  4. Passo 4: WHEN MATCHED - DELETE

  5. Passo 5: WHEN NOT MATCHED - INSERT
    
  Se a linha existe na fonte, mas não na tabela de destino...

  INSERT (...) VALUES (...) - Uma nova linha é inserida na tabela de destino com os valores provenientes da fonte.
