Aula - Ingestão de Dados do Cloud Storage

Visão Geral

Nesta aula, você aprenderá como arquivos brutos do cloud storage podem ser convertidos de forma eficiente em tabelas UC usando as ferramentas do Databricks, desbloqueando capacidades avançadas de gerenciamento e analítica dentro do Lakehouse.

Objetivos de Aprendizagem

Ao final desta aula, você será capaz de:

  1. Demonstrar como realizar a ingestão de dados do armazenamento de objetos em cloud para tabelas UC usando CREATE TABLE AS, COPY INTO e Auto Loader, incluindo a captura de metadados do arquivo de Entrada em tabelas da camada Bronze
  2. Explicar como as colunas resgatadas são utilizadas durante a ingestão para gerenciar registros malformados

A. Padrões de Ingestão de Dados do Cloud Object Storage

A ingestão de dados é um componente crítico da arquitetura moderna de Lakehouse, permitindo que as organizações aproveitem grandes volumes de dados armazenados em sistemas de armazenamento de objetos em cloud.

  • Formatos de arquivo comuns como CSV, JSON e Parquet são amplamente utilizados devido à sua flexibilidade e facilidade de uso.
  • Nosso objetivo é converter esses arquivos brutos em tabelas do UC, desbloqueando funcionalidades avançadas como transações ACID, viagem do tempo e imposição de esquema.

  • A ingestão a partir do armazenamento de objetos cloud é realizada usando os Conectores Padrão do LakeFlow Connect.

B. Métodos de Ingestão de Dados

Ao realizar a ingestão de dados no Databricks usando os Conectores Padrão do LakeFlow Connect, você pode escolher entre diferentes métodos de ingestão.

Clique nas abas para alternar entre os métodos de ingestão.

Método 1 - Lotes -
CREATE TABLE AS (CTAS)
CREATE TABLE new_table AS SELECT * FROM read_files( <path_to_file(s)>, format => '<file_type>', <other_format_specific_options> );

CREATE TABLE AS (CTAS) cria uma tabela UC por default a partir de arquivos no armazenamento de objetos cloud.

A função read_files() lê arquivos em um local fornecido e retorna os dados em formato tabular.
Método 2 - Lotes Incrementais -
COPY INTO
CREATE TABLE new_table;
COPY INTO new_table FROM '<dir_path>' FILEFORMAT = <file_type> FORMAT_OPTIONS (<options>) COPY_OPTIONS (<options>)

Use o comando COPY INTO para copiar arquivos do armazenamento cloud para a tabela UC; isso realiza uma carga em massa de arquivos do armazenamento de objetos cloud para a tabela.

O COPY INTO ignorará quaisquer arquivos que já tenham sido carregados na tabela, e somente os novos arquivos serão ingeridos.
Método 3 - Lotes Incrementais ou Transmissão -
AUTO LOADER

EXPANDIR PARA NOTAS ADICIONAIS
  • CREATE TABLE AS (CTAS)
    1. Suporta leitura de formatos de arquivo como:
      | JSON | CSV | XML | TEXT | BINARYFILE | PARQUET | AVRO | ORC
    2. Pode detectar o formato do arquivo automaticamente e inferir um esquema unificado em todos os arquivos.
    3. Especifique opções de formato de arquivo específicas para ler os dados com base no formato do arquivo fonte.
    4. Pode ser usado em tabelas de transmissão para ingerir arquivos de forma incremental no Delta Lake usando o Auto Loader.

  • COPY INTO
    Use o comando COPY INTO para copiar arquivos do armazenamento cloud para a tabela do Unity Catalog. Este comando realiza um carregamento em massa de arquivos do armazenamento de objetos cloud para a tabela e, neste exemplo, carregará os arquivos na tabela vazia new_table. A cláusula FROM especifica o local dos arquivos CSV.

    • COPY INTO é ideal para situações em que o local de armazenamento cloud está continuamente recebendo novos arquivos, pois é uma operação repetível e idempotente projetada para ingestão de dados em lotes de forma incremental. Aspectos principais do COPY INTO:
    • Idempotente: Ignorará qualquer arquivo que já tenha sido carregado na tabela; somente novos arquivos serão ingeridos
    • Suporte a formatos de arquivo: Parquet, JSON, XML e outros
    • Cláusula FROM: Especifica o caminho do local de armazenamento cloud onde novos arquivos estão sendo adicionados continuamente
    • FORMAT_OPTIONS(): Controla como os arquivos fonte são analisados e interpretados (as opções dependem do formato do arquivo)
    • COPY_OPTIONS(): Controla o comportamento da própria operação COPY INTO, como:
      • Evolução do esquema usando (mergeSchema)
      • Idempotência usando (force)

  • AUTO LOADER
    1. Ingestão em lotes incremental ou de transmissão usando o Auto Loader.
      • Processar novos arquivos de dados de forma incremental à medida que chegam ao armazenamento cloud (em lotes ou transmissão)
      • Ingerir dados sem configuração extra ou configuração complexa
      • Detectar e carregar automaticamente novos arquivos em tabelas do Unity Catalog
      • Simplificar o tratamento de dados incrementais e de transmissão
      • Usar com Python e SQL (via Declarative Pipelines)
      • Escalar para processar bilhões de arquivos
      • Basear-se no Spark Structured Streaming para ingestão eficiente e confiável

    2. Auto Loader em Python para ler dados de transmissão do armazenamento cloud:
      • Começamos com .readStream e definimos o formato como "cloudFiles", o que habilita o Auto Loader.
      • Em seguida, especificamos o formato do arquivo como JSON e definimos o local do esquema usando cloudFiles.schemaLocation, que é utilizado para rastrear a inferência e a evolução do esquema.
      • Depois, usamos .load() para apontar para o local dos arquivos, neste caso um caminho em /Volumes referenciando o Unity Catalog.
      • No lado de escrita, configuramos .writeStream com um local de checkpoint para manter o estado e o progresso, e definimos um intervalo de gatilho de a cada 5 segundos.
      • Por fim, usamos .toTable() para gravar os dados em uma tabela do Unity Catalog especificada pelo catálogo, banco de dados e nome da tabela.

    3. Auto Loader com Databricks SQL
      • O Databricks recomenda o uso de tabelas de transmissão para ingerir dados com o Databricks SQL (em vez de COPY INTO). Uma tabela de transmissão é uma tabela registrada no Unity Catalog que inclui suporte adicional para processamento de dados em transmissão ou incremental.
        • Quando você cria uma tabela de transmissão, um pipeline é gerado automaticamente para ela.
        • As tabelas de transmissão podem ser usadas para carregamento incremental de dados tanto do Kafka quanto do armazenamento de objetos cloud.
      • Para criar uma tabela de transmissão a partir de arquivos em um volume, você usa o Auto Loader. O Databricks recomenda usar o Auto Loader com Apache Spark™ Declarative Pipelines para a maioria das tarefas de ingestão de dados do armazenamento de objetos cloud. Juntos, o Auto Loader e o Declarative Pipelines são projetados para carregar de forma incremental e idempotente conjuntos de dados em crescimento contínuo à medida que chegam.
      • As tabelas de transmissão no Databricks SQL são suportadas por Spark Declarative Pipelines serverless. Seu workspace deve suportar pipelines serverless para usar essa funcionalidade. Alternativamente, você pode criar seus próprios Spark Declarative Pipelines para processamento incremental, otimização e monitoramento. O Declarative Pipelines oferece uma variedade de recursos adicionais, sobre os quais você pode aprender mais aqui.
      • Para usar o Auto Loader no Databricks SQL, utilize a função read_files com a palavra-chave STREAM na cláusula FROM.

D. Conclusão

Nesta aula, você aprendeu os três métodos principais para ingestão de dados de armazenamento de objetos cloud em tabelas UC:

  • CREATE TABLE AS (CTAS): Ingestão em lotes usando read_files() que cria tabelas UC a partir de arquivos brutos. Ideal para conjuntos de dados menores e ad hoc.
  • COPY INTO: Ingestão incremental em lotes que é idempotente e repetível. Ignora arquivos já carregados e oferece suporte a opções de formato e cópia para controle refinado.
  • AUTO LOADER: O método mais escalável, construído sobre Spark Structured Streaming. Oferece suporte a Python e SQL (via Declarative Pipelines), processa bilhões de arquivos e lida automaticamente com a evolução do esquema.
